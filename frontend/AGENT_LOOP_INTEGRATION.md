# Autonomous Agent Loop Backend Integration Guide

This guide explains how the **Autonomous Agent Loop** UI section in the chat is updated dynamically from the backend, including the WebSocket message specifications and data models.

---

## 1. Dynamic vs. Fixed Behavior
The Autonomous Agent Loop section is **fully dynamic**. The React frontend renders it via the [`AgentPhaseViewer.tsx`](file:///d:/Sentinal/sentinal-frontend/src/components/AgentPhaseViewer.tsx) component, which listens in real-time to WebSocket messages sent by the backend. It transitions through planning, evaluation, building, and output phases, printing execution logs, tool run state, and artifacts as they happen.

---

## 2. Event Lifecycle & WebSocket Envelopes

The backend coordinates the agent loop status updates by broadcasting messages wrapped in the **Universal WebSocket Envelope** format:

```json
{
  "type": "discriminator_type",
  "session_id": "conv-unique-session-id",
  "seq": 1, // Monotonically increasing sequence number
  "timestamp": "2026-08-31T01:35:00.000Z",
  "payload": { ... }
}
```

Here is the event sequence generated by the backend during an active agent run:

### Step 1: Initializing the Plan (`plan` event)
When the agent starts processing, the backend must construct the plan steps and dispatch a `"plan"` type event containing the initial list of tasks.

```json
{
  "type": "plan",
  "session_id": "conv-12345",
  "seq": 3,
  "timestamp": "2026-08-31T01:35:01.000Z",
  "payload": {
    "steps": [
      {
        "id": "p1",
        "phase": "planning",
        "title": "Parse query parameters",
        "description": "Decomposing query, determining scope, and verifying resource bounds.",
        "status": "running",
        "logs": ["Analyzing prompt targets...", "Selected model-reasoning-qwen for layout parsing"],
        "durationMs": 0
      },
      {
        "id": "p2",
        "phase": "evaluation",
        "title": "Inspect project workspace",
        "description": "Evaluating execution constraints and verifying pre-conditions.",
        "status": "pending",
        "logs": [],
        "durationMs": 0
      },
      {
        "id": "p3",
        "phase": "building",
        "title": "Synthesize report and output structures",
        "description": "Formulating final output response and writing artifact assets.",
        "status": "pending",
        "logs": [],
        "durationMs": 0
      }
    ]
  }
}
```

### Step 2: Updating Plan Progress & Logs
As the agent progresses, you send updated `"plan"` payloads reflecting state changes (e.g. changing `status` to `"completed"` or `"failed"` and appending `logs` to the active step).

*   **Step Statuses:** `'pending' | 'running' | 'completed' | 'failed'`
*   **Phases:** `'planning' | 'evaluation' | 'building' | 'output'`

### Step 3: Integrating Sandbox Tool Calls
During the `"evaluation"` or `"building"` phase, you can dispatch sandbox execution logs or tool calls by adding them to the relevant step's `toolCalls` array inside your `"plan"` payload:

```json
{
  "type": "plan",
  "session_id": "conv-12345",
  "seq": 4,
  "payload": {
    "steps": [
      {
        "id": "p1",
        "phase": "planning",
        "title": "Parse query parameters",
        "status": "completed",
        "logs": ["Analyzing prompt targets...", "Selected model-reasoning-qwen for layout parsing"],
        "durationMs": 850
      },
      {
        "id": "p2",
        "phase": "evaluation",
        "title": "Inspect project workspace",
        "status": "running",
        "logs": ["Executing inspection script inside sandbox"],
        "durationMs": 400,
        "toolCalls": [
          {
            "toolId": "tool-code-execution",
            "toolName": "code_execution",
            "inputParams": { "command": "python verify_env.py" },
            "outputResult": "Environment check passed: Python 3.10, libraries verified.",
            "durationMs": 400,
            "status": "success"
          }
        ]
      },
      {
        "id": "p3",
        "phase": "building",
        "title": "Synthesize report and output structures",
        "status": "pending",
        "logs": [],
        "durationMs": 0
      }
    ]
  }
}
```

### Step 4: Generating Artifacts & Completing the Run (`final` event)
Once the task finishes, the backend closes the turn and locks the agent loop status by sending a `"final"` type event containing:
*   `content`: The ultimate markdown text reply.
*   `total_duration_ms`: Duration of the overall agent loop execution.
*   `tokens_used`: Consumption telemetry.

```json
{
  "type": "final",
  "session_id": "conv-12345",
  "seq": 8,
  "timestamp": "2026-08-31T01:35:10.000Z",
  "payload": {
    "message_id": "msg-172504891000",
    "content": "All analysis completed. The environment validation reports no issues.",
    "tokens_used": 680,
    "tokens_per_sec": 55.2,
    "total_duration_ms": 9000
  }
}
```

## 3. Data Structure Reference (Typescript Schema)

The state updates in [`App.tsx`](file:///d:/Sentinal/sentinal-frontend/src/App.tsx#L192-L217) expect the `AgentRunDetails` schema matching the TypeScript model specified in [`types.ts`](file:///d:/Sentinal/sentinal-frontend/src/types.ts#L150-L157):

```typescript
export interface AgentRunDetails {
  currentPhase: 'planning' | 'evaluation' | 'building' | 'output';
  steps: AgentStep[];
  progressPercent: number; // e.g. 0 to 100
  totalDurationMs: number;
  isFinished: boolean;
  thoughtSummary?: string; // Appears right under "Autonomous Agent Loop" header
}

export interface AgentStep {
  id: string;
  phase: 'planning' | 'evaluation' | 'building' | 'output';
  title: string;
  description: string;
  status: 'pending' | 'running' | 'completed' | 'failed';
  logs: string[]; // execution lines printed in trace logs container
  toolCalls?: ToolCallExecution[];
  artifacts?: AgentArtifact[];
  durationMs?: number;
}

export interface ToolCallExecution {
  toolId: string;
  toolName: string;
  inputParams: Record<string, any>;
  outputResult: any;
  durationMs: number;
  status: 'pending' | 'running' | 'success' | 'failed';
}

export interface AgentArtifact {
  id: string;
  title: string;
  type: 'code' | 'file' | 'diff' | 'json' | 'markdown';
  language?: string;
  content: string;
}
```
